# 前后端接口集成映射总表

> 版本：v1.0 · 生成日期：2026-09-30
> 范围：后端 137 个 `/v1/*` RESTful 接口 ↔ 前端 18 个管理页 + 公共页面
> 统一约定：前端一律通过 `js/api-request.js`（`window.QAXQJT_API`）调用，路径取自 `js/api-config.js` 的 `PATHS` 常量，禁止硬编码 URL。

---

## 一、架构总览

```
┌──────────────────────────────────────────────────────────────┐
│  前端（admin/*.html + 根目录公共页）                          │
│    ├─ js/api-config.js  → window.QAXQJT_API_CONFIG.PATHS     │
│    │   （137 个端点路径常量，单一数据源）                     │
│    └─ js/api-request.js → window.QAXQJT_API                  │
│        （get/post/put/patch/del，Bearer 自动注入，401 刷新）  │
└──────────────────────┬───────────────────────────────────────┘
                       │  nginx 同源代理 /api → :3001
                       ▼
┌──────────────────────────────────────────────────────────────┐
│  后端（Koa + Prisma，PM2: qaxqjt-api @ :3001）                │
│    18 个模块 · 137 个 v1 端点 · JWT 鉴权 · RBAC 角色权限      │
└──────────────────────────────────────────────────────────────┘
```

**关键约束**：
- `schedule.html` 使用自包含的 `js/schedule-bundle.js`（内含 api-config + api-request 副本），修改路径时必须**两处同步**。
- 后端集合路径用单数名词（`/v1/attendance`、`/v1/fin/ledger`），勿写成复数或连字符。
- 分页接口统一返回 `{ items, meta: { page, pageSize, total } }`；列表接口可能直接返回数组。

## 四、鉴权与数据流规范

### 4.1 鉴权流程
1. 登录成功后后端返回 `{ token, refreshToken, user }`，前端存入 `localStorage`。
2. 每次请求 `api-request.js` 自动注入 `Authorization: Bearer <token>`。
3. 收到 401 时，对**幂等方法**（GET/PUT/DELETE/补丁）自动调用 `/v1/auth/refresh` 刷新后重试一次；非幂等（POST）直接抛出由页面提示。
4. 刷新失败则清除本地凭证并跳转 `login.html`。

### 4.2 统一响应格式
```json
{ "code": 0, "data": {...}, "message": "ok", "meta": { "page": 1, "pageSize": 20, "total": 100 } }
```
- `code === 0` 表示成功，`api-request.js` 自动解包返回 `data`。
- 业务错误 `code !== 0` 抛出异常，由页面 try/catch 处理并 toast 提示。

### 4.3 RBAC 权限
- 后端每个路由挂 `requireRole([...])` 中间件，当前用户角色不满足返回 403。
- 前端通过 `GET /v1/auth/me` 获取 `permissions` 数组，用于菜单/按钮级显隐控制。
- 角色权限分配通过 `PUT /v1/roles/:id/permissions` 提交 `permissionIds` 全量覆盖。
