## ⚠️ P0 阻断项（执行前必须全部 ✅，未通过不得上线）

| # | 检查项 | 验证方式 | 不通过后果 |
|---|--------|---------|-----------|
| P0-1 | **数据库版本达标**：MySQL ≥ 8.0.19 **或** PostgreSQL ≥ 13.7 | `SELECT version();` | 不支持 CHECK 约束、JSON 字段索引、utf8mb4_0900_ai_ci |
| P0-2 | **数据库字符集**：MySQL `SHOW VARIABLES LIKE 'character_set%'` 全部 = utf8mb4 / PostgreSQL `SHOW SERVER_ENCODING` = UTF8 | 执行 SQL 查询 | 中文乱码、无法存 emoji（📞🎫🎭） |
| P0-3 | **数据库 InnoDB/引擎**：MySQL `default_storage_engine=InnoDB`，或 PG 使用默认 heap | `SHOW ENGINES;` | MyISAM 不支持事务/外键/行锁 |
| P0-4 | **后端运行时**：Node.js ≥ 18 LTS **或** Java 17+ **或** Python 3.9+（任选 1 栈） | `node -v` / `java -version` / `python3 --version` | 依赖包语法不兼容 |
| P0-5 | **HTTPS 证书**：生产域名已配置 DV 以上 SSL，浏览器地址栏无警告 | 浏览器访问 + `openssl s_client` | Cookie Secure 标志失效、微信/支付宝回调拦截 |
| P0-6 | **域名备案**：`.cn` 域名 ICP 备案 + 公安备案双完成 | 工信部 + 公安系统查询 | 运营商阻断 80/443 |
| P0-7 | **初始管理员 bcrypt 密码哈希**：已由后端本地生成，**禁止在 SQL 明文写密码** | `bcrypt.hash(password, 12)` 生成 | 撞库风险 + 合规审计不通过 |

## 🔐 三、鉴权链路部署（对应 E-2 全文）

### 3.1 五个核心鉴权接口联调顺序
```
  1. GET  /v1/auth/csrf-token        → 前端取双随机 token（Cookie: _csrf + Header: X-CSRF-Token）
  2. POST /v1/auth/login             → 账号密码 + CSRF → 返回 Set-Cookie: sid (HttpOnly+Secure+SameSite=Lax)
  3. GET  /v1/auth/me                → 带 sid 读当前账号（前端判断是否登录）
  4. POST /v1/auth/refresh-session   → 30min 自动续期（滑动过期）
  5. POST /v1/auth/logout            → 服务端 session 销毁 + 前端清 Cookie
```

### 3.2 Session/Cookie 关键配置
```javascript
// Node + Express 示例（上线必须与 E-2 §三完全一致）
session({
  name: 'qaxqjt_sid',            // 不使用默认 connect.sid
  secret: process.env.SESSION_SECRET || '<openssl rand -hex 32 生成>',
  resave: false,
  saveUninitialized: false,
  store: new RedisStore({ client: redisClient, prefix: 'qaxqjt:sess:', ttl: 86400 * 7 }),
  cookie: {
    httpOnly: true,              // ✅ 禁 JS 读（防 XSS 偷会话）
    secure: process.env.NODE_ENV === 'production',  // ✅ 生产只走 HTTPS
    sameSite: 'lax',             // ✅ 防 CSRF 第三方提交
    maxAge: 1000 * 60 * 60 * 24 * 7,  // 7 天（配合 refresh 续期）
    domain: process.env.NODE_ENV === 'production' ? '.yourdomain.cn' : undefined
  }
})
```

## 🛡️ 六、安全 & 审计 & 合规

### 6.1 安全配置（对应 E-3 安全加固手册）
| # | 项目 | 配置 | 审计方法 |
|---|------|------|---------|
| S-1 | 密码哈希算法 | **bcrypt cost=12 / argon2id m=65536,t=3,p=4** | 查 `accounts_v2.password_hash` 前缀 `$2b$12$` / `$argon2id$` |
| S-2 | 财务物理删禁止 | `fin_ledger_v1.is_void` + 留痕，禁止 `DELETE` | 代码里 grep DELETE FROM fin_ledger |
| S-3 | 越权 403 告警 | 每次 403 → 企业微信/钉钉机器人 @所有人 | 测试用低权限账号访问 `/v1/admin/accounts` |
| S-4 | 备份下载审计 | 每次 `GET /v1/admin/system/backup-download` → 推送运维群 + 审计表 | 触发一次看群消息 |
